# AI議事録・タスク抽出ツール

会議の音声をリアルタイムで文字起こしし、その内容をAIが要約・タスク抽出するツールです。
**クラウドAPIを一切使わず、無料で完結する構成**にこだわって開発しました。

- デモ動画: [demo.mov](demo.mov)

---

## 🎯 採用担当の方へ（30秒で分かる要約）

**これは何か**：会議の音声を文字起こしし、AIが要約・TODO抽出まで行うツールです。音声認識も要約もすべてローカルで完結し、外部にデータを送信しません。

このプロジェクトから伝わればと思っている点です。

- **クラウド依存にしない、という技術選定をしている**：文字起こしはブラウザ標準のWeb Speech API、要約はローカルLLM（Ollama / gemma2）を使い、外部APIの従量課金なしで完結する構成にしています。「社外秘の会議内容を外部に送りたくない」という利用者側の懸念を、機能ではなく構成で解決しています。
- **段階的に作り直す進め方をしている**：まずプレーンJS（`index.html`）で機能を素早く検証し、動作確認できた後にReact版（`frontend/`）へコンポーネント単位で作り直しています。最初から完璧な設計を狙うのではなく、検証→整理の順で進める姿勢が伝わればと思います。
- **二重実装によるロジックの乖離を避けている**：フロントエンドは2系統ありますが、バックエンド（`server.js`）は共通化しており、同じ処理を2箇所に書かない設計にしています。
- **無料で完結させる制約に向き合っている**：従量課金のクラウドAPIを使わないという条件のもとで、精度と実用性のバランスを取っています。

## 1. 背景・課題

会議の議事録作成は、多くの現場で「誰かがやらなければいけないが、時間がかかる」作業です。クラウド型の議事録ツールも存在しますが、

- 会議内容によっては、外部の音声認識・AI APIに社外秘の内容を送りたくない
- 個人・小規模チームでは、月額課金のツールを導入しづらい

という課題があると考え、**音声認識はブラウザ内、要約はローカルLLM**で完結させることで、外部にデータを一切送信せず、かつ無料で使えるツールとして開発しました。

## 2. 要件定義

### 2.1 想定ユーザー

- 社外に出せない内容の会議が多く、クラウドAPIを使った議事録ツールを導入しづらいチーム
- 個人開発・小規模チームで、議事録ツールに月額コストをかけたくない人

### 2.2 機能要件

| ID | 要件 | 対応状況 |
|---|---|---|
| F-1 | ブラウザの録音ボタンで音声入力を開始・停止できる | ✅ |
| F-2 | 話した内容をリアルタイムで文字起こしする | ✅ |
| F-3 | 文字起こし結果からAIが要約とTODOリストを生成する | ✅ |
| F-4 | 議事録（文字起こし・要約・TODO）を自動でデータベースに保存する | ✅ |
| F-5 | 過去の議事録を一覧で確認できる | ✅ |
| F-6 | プレーンJS版・React版の2つの実装を選べる | ✅ |

### 2.3 非機能要件

| 区分 | 内容 |
|---|---|
| プライバシー | 音声認識はブラウザ標準のWeb Speech APIを使用し、要約はローカルで動くOllama(gemma2)を使用。文字起こし・要約のいずれも外部サーバーに送信しない |
| コスト | 従量課金のクラウドAPIを一切使わず、完全無料。インターネット接続がなくても動作する（Ollamaがローカルで動いていれば） |
| 保守性 | フロントエンドをプレーンJS版とReact版の2系統で用意しつつ、バックエンド(`server.js`)は共通化し、二重実装によるロジックの乖離を避けている |

## 3. アーキテクチャ

```
ブラウザ（Web Speech API）
   │  音声 → テキスト（文字起こし、ブラウザ内で完結）
   ▼
フロントエンド（index.html または frontend/）
   │  文字起こし結果を POST /summarize
   ▼
バックエンド（server.js / Express）
   │  Ollama（ローカルLLM）にプロンプトを送信
   ▼
Ollama（gemma2、ローカル実行）
   │  要約 + TODOリストをJSONで返す
   ▼
バックエンドが SQLite に保存 → フロントに返却
```

## 4. 画面・実装構成

このリポジトリには2つのフロントエンド実装が含まれる。

| バージョン | 場所 | 概要 |
|---|---|---|
| プレーンJS版 | `index.html` | HTML/CSS/JavaScriptのみで実装した初期バージョン |
| React版 | `frontend/` | `Recorder`（録音UI）/ `Summary`（要約・TODO表示）/ `History`（過去の議事録一覧）の3コンポーネントに分割し、Reactで作り直したバージョン |

どちらもバックエンド(`server.js`)は共通。プレーンJS版で機能を検証し、React版でコンポーネント単位の設計に作り直す、という段階的な進め方をしている。

## 5. データ設計

```
meetings
├─ id           INTEGER PRIMARY KEY AUTOINCREMENT
├─ transcript   TEXT   -- 文字起こし全文
├─ summary      TEXT   -- AIによる要約
├─ todos        TEXT   -- JSON文字列として保存したTODOリスト
└─ created_at   TEXT (default CURRENT_TIMESTAMP)
```

## 6. API仕様

| Method | Path | 概要 |
|---|---|---|
| POST | `/summarize` | 文字起こしテキストを受け取り、Ollamaに要約・TODO抽出をリクエスト。結果をDBに保存して返す |
| GET | `/meetings` | 保存済みの議事録一覧を新しい順で返す |

## 7. 技術選定

| 分野 | 技術 | 採用理由 |
|---|---|---|
| 音声認識 | Web Speech API | ブラウザ標準機能のみで音声→テキストを実現し、外部送信・追加コストをゼロにするため |
| AI要約・タスク抽出 | Ollama (gemma2) | ローカルで動くLLMを使うことで、要約処理も外部APIに依存させないため |
| バックエンド | Node.js / Express | 最小構成でOllamaへのプロキシ役を実装するため |
| データベース | SQLite (better-sqlite3) | 個人利用規模では十分な永続化手段として、セットアップの手軽さを優先 |
| フロントエンド | HTML/CSS/JS → React | まずプレーンJSで動くものを作り、後からコンポーネント単位の設計に作り直す進め方 |

## 8. セットアップ

### 8.1 前提ソフト

- [Node.js](https://nodejs.org/)（LTS版）
- [Ollama](https://ollama.com/)

### 8.2 モデルのダウンロード

```bash
ollama run gemma2
```

初回はモデル（約5.4GB）のダウンロードが始まる。ダウンロード後は`/bye`で一旦抜けてよい。

### 8.3 クローン・依存パッケージのインストール

```bash
git clone https://github.com/yukisatodev/meeting-notes.git
cd meeting-notes
npm install
```

### 8.4 バックエンドサーバーの起動

```bash
node server.js
```

`サーバー起動: http://localhost:3000`と表示されれば起動完了。プレーンJS版・React版どちらを使う場合も、このバックエンドは共通で必要。

### 8.5-A プレーンJS版を使う場合

`index.html`をダブルクリックしてブラウザ（Google Chrome推奨）で開く。

### 8.5-B React版を使う場合

別のターミナルで以下を実行する。

```bash
cd frontend
npm install
npm run dev
```

`Local: http://localhost:5173/`と表示されるURLをブラウザで開く。

## 9. 使い方

1. 「録音開始」を押して話す（初回はマイクの使用許可が必要）
2. 「停止」を押して録音終了
3. 「要約・タスク抽出」を押すと、AIが要約とTODOリストを生成
4. 「過去の議事録を見る」で、過去の議事録を一覧確認できる
